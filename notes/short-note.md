I designed Relay as a focused team file-transfer workspace rather than a broad cloud storage product. The main product decision was to prioritize fast scanning and triage: recent transfers, status folders, search/filter controls, and a persistent transfer details panel. I treated transfer status as a core workflow signal, so active, expiring soon, expired, and disabled links are visible throughout the UI.
I kept the app client-side with realistic mock data only, as requested. I added small simulated interactions where they improve the prototype: copy link feedback, favorite state, disable/enable, extend expiry, theme persistence, and non-happy states. I also spent time polishing responsive behavior, first-load splash motion, theme loading, and deployment details like static assets.
The main trade-off is that this is not a full production system. There is no backend, authentication, upload flow, database, real activity log, or public recipient page. Settings are included as a realistic shell, but they do not save to a server. I chose this scope to keep the project small, polished, and aligned with the task’s focus on product thinking, UX, and clean implementation.
I used Claude to help shape the project PRD, clarify the design direction, and refine the UI/UX path. I used Codex for AI-assisted coding, implementation, debugging, and verification. Final checks included npm run lint, npm run build, and browser smoke tests for the splash animation, theme behavior, logo loading, navigation, transfer details, mobile flow, and key interactions.
